## 1. Overview & Introduction

### What are Static Files?

Static files are resources that your web server sends directly to the browser without any processing or modification. These files include CSS stylesheets, JavaScript files, images, fonts, and other assets that don't change based on the user or request. Unlike dynamic content generated by your C# code, static files are served exactly as they exist on disk.

In ASP.NET Core MVC, static files are stored in the `wwwroot` folder and are made available to browsers through the Static Files middleware. When a user requests `/css/site.css`, the middleware finds and serves `wwwroot/css/site.css` without involving controllers or Razor views.

### What is wwwroot?

The `wwwroot` folder is a special directory in ASP.NET Core that serves as the web root - the publicly accessible folder for your application. Only files inside `wwwroot` can be accessed directly by browsers. This security-by-default approach means your source code, configuration files, and other sensitive files outside `wwwroot` are protected from direct web access.

Think of `wwwroot` as your application's public folder - everything inside is published to the web, everything outside is private.

### Why Use Static Files?

Static files are essential for web applications because they:

- **Provide styling** - CSS files make your pages look professional and visually appealing
- **Add interactivity** - JavaScript files enable dynamic behavior and rich user experiences
- **Display media** - Images, videos, and fonts enhance content and branding
- **Improve performance** - Static files can be cached by browsers, reducing server load
- **Separate concerns** - Keep frontend assets organized separately from backend code
- **Enable CDN delivery** - Static files can be offloaded to Content Delivery Networks for faster loading

### When to Use Static Files vs Dynamic Content

**Use static files for:**
- CSS stylesheets that apply to all pages
- JavaScript libraries and custom scripts
- Images, logos, icons
- Fonts
- PDF downloads, documents
- Favicon and other browser assets
- Files that rarely change

**Use dynamic content (controllers/views) for:**
- HTML that changes based on data or user
- Personalized content
- Forms that need server-side processing
- Content requiring authentication checks
- Pages that display database information

### Common Static File Types

**Stylesheets (CSS)**
- `.css` - Cascading Style Sheets for visual styling
- Purpose: Control layout, colors, fonts, responsive design

**Scripts (JavaScript)**
- `.js` - JavaScript files for client-side logic
- Purpose: Interactivity, AJAX calls, form validation

**Images**
- `.jpg`, `.jpeg` - Photos and complex images
- `.png` - Images with transparency
- `.gif` - Simple animations
- `.svg` - Scalable vector graphics
- `.ico` - Favicons

**Fonts**
- `.woff`, `.woff2` - Web fonts (most common)
- `.ttf`, `.otf` - TrueType and OpenType fonts

**Documents**
- `.pdf` - Portable documents
- `.txt` - Plain text files

## 2. Initial Setup & Configuration

### Understanding the wwwroot Folder Structure

A typical ASP.NET Core MVC project organizes static files in `wwwroot`:

```
wwwroot/
├── css/                    # Stylesheets
│   ├── site.css           # Your custom styles
│   └── ...
├── js/                     # JavaScript files
│   ├── site.js            # Your custom scripts
│   └── ...
├── lib/                    # Third-party libraries
│   ├── bootstrap/         # Bootstrap files
│   ├── jquery/            # jQuery files
│   └── ...
├── images/                 # Image files
│   ├── logo.png
│   ├── banner.jpg
│   └── ...
├── fonts/                  # Custom fonts
│   └── ...
├── documents/              # Downloadable files
│   └── ...
└── favicon.ico             # Site favicon
```

**Naming conventions:**
- Use lowercase for folder and file names
- Separate words with hyphens: `pokemon-card.css`
- Avoid spaces in file names
- Use descriptive names: `hero-banner.jpg` not `img1.jpg`

### Configuring Static Files Middleware

Static files are enabled in `Program.cs` with the `UseStaticFiles()` middleware:

**Program.cs (default configuration):**

```csharp
var builder = WebApplication.CreateBuilder(args);

// Add services
builder.Services.AddControllersWithViews();

var app = builder.Build();

// Configure middleware pipeline
if (!app.Environment.IsDevelopment())
{
    app.UseExceptionHandler("/Home/Error");
    app.UseHsts();
}

app.UseHttpsRedirection();

// Enable static files from wwwroot
app.UseStaticFiles();

app.UseRouting();
app.UseAuthorization();

app.MapControllerRoute(
    name: "default",
    pattern: "{controller=Home}/{action=Index}/{id?}");

app.Run();
```

**Key points:**
- `UseStaticFiles()` must be called before `UseRouting()`
- By default, only files in `wwwroot` are served
- No controller or action is needed to serve static files

### Serving Files from Custom Locations (Advanced)

You can serve static files from folders outside `wwwroot`:

```csharp
using Microsoft.Extensions.FileProviders;

// Serve files from custom folder
app.UseStaticFiles(new StaticFileOptions
{
    FileProvider = new PhysicalFileProvider(
        Path.Combine(builder.Environment.ContentRootPath, "MyStaticFiles")),
    RequestPath = "/StaticFiles"
});
```

**Example:**
- File location: `MyStaticFiles/image.jpg`
- Browser URL: `https://yoursite.com/StaticFiles/image.jpg`

**Common use case:** Serving uploaded user files from a separate folder.

### Setting Cache Headers

Configure caching for better performance:

```csharp
app.UseStaticFiles(new StaticFileOptions
{
    OnPrepareResponse = ctx =>
    {
        // Cache static files for 7 days
        ctx.Context.Response.Headers.Append(
            "Cache-Control", "public,max-age=604800");
    }
});
```

### Enabling Directory Browsing (Not Recommended for Production)

For development, you might want to browse folders:

```csharp
// Enable directory browsing (development only!)
app.UseDirectoryBrowser(new DirectoryBrowserOptions
{
    FileProvider = new PhysicalFileProvider(
        Path.Combine(builder.Environment.ContentRootPath, "wwwroot")),
    RequestPath = "/files"
});
```

**Warning:** Never enable directory browsing in production - it exposes your file structure.

### Verifying Static Files Work

**Test 1: Create a test file**

Create `wwwroot/test.html`:

```html
<!DOCTYPE html>
<html>
<head>
    <title>Static File Test</title>
</head>
<body>
    <h1>Static files are working!</h1>
    <p>If you can see this, wwwroot is configured correctly.</p>
</body>
</html>
```

**Test 2: Access in browser**

Navigate to: `https://localhost:5001/test.html`

If you see the page, static files are working correctly.

## 3. Basic Usage

### Referencing Static Files in Razor Views

ASP.NET Core provides the `~` symbol to reference the wwwroot folder:

**Basic reference:**

```cshtml
<!-- CSS -->
<link rel="stylesheet" href="~/css/site.css" />

<!-- JavaScript -->
<script src="~/js/site.js"></script>

<!-- Image -->
<img src="~/images/logo.png" alt="Logo" />
```

The `~` resolves to the wwwroot path: `~/css/site.css` becomes `/css/site.css`

### Using asp-append-version for Cache Busting

Add version hashes to prevent browser caching issues:

```cshtml
<link rel="stylesheet" href="~/css/site.css" asp-append-version="true" />
<script src="~/js/site.js" asp-append-version="true"></script>
```

**Result:**
```html
<link rel="stylesheet" href="/css/site.css?v=abc123def456" />
```

The hash changes when the file changes, forcing browsers to download the new version.

### Working with JavaScript Files

**Create custom script:**

**wwwroot/js/pokemon.js:**

```javascript
// Pokemon utility functions

function showPokemonDetails(id) {
    console.log('Loading Pokemon ID: ' + id);

    // Load via AJAX
    $.ajax({
        url: '/api/pokemon/' + id,
        type: 'GET',
        success: function(pokemon) {
            displayPokemon(pokemon);
        },
        error: function() {
            alert('Failed to load Pokemon');
        }
    });
}

function displayPokemon(pokemon) {
    var html = `
        <h2>${pokemon.name}</h2>
        <p>Type: ${pokemon.type}</p>
        <p>Level: ${pokemon.level}</p>
    `;
    $('#pokemon-details').html(html);
}

// Initialize when page loads
$(document).ready(function() {
    console.log('Pokemon scripts loaded');

    // Add click handlers
    $('.pokemon-card').on('click', function() {
        var id = $(this).data('id');
        showPokemonDetails(id);
    });
});
```

**Reference in view:**

```cshtml
@section Scripts {
    <script src="~/js/pokemon.js" asp-append-version="true"></script>
}
```

## 4. Common Patterns & Best Practices

### File Organization Best Practices

#### Pattern 1: Organize by Type

```
wwwroot/
├── css/
│   ├── site.css              # Global styles
│   ├── pokemon.css           # Pokemon-specific styles
│   ├── forms.css             # Form styles
│   └── admin.css             # Admin-specific styles
├── js/
│   ├── site.js               # Global scripts
│   ├── pokemon.js            # Pokemon functionality
│   ├── validation.js         # Form validation
│   └── admin.js              # Admin scripts
└── images/
    ├── pokemon/              # Organized by category
    ├── icons/
    └── backgrounds/
```

**Benefits:**
- Clear separation of concerns
- Easy to find files
- Simple to maintain

#### Pattern 2: Organize by Feature

```
wwwroot/
├── home/
│   ├── home.css
│   ├── home.js
│   └── home-banner.jpg
├── pokemon/
│   ├── pokemon.css
│   ├── pokemon.js
│   └── sprites/
├── trainer/
│   ├── trainer.css
│   ├── trainer.js
│   └── badges/
└── shared/
    ├── layout.css
    ├── navigation.js
    └── common-icons/
```

**Benefits:**
- All related files together
- Easier to delete unused features
- Better for large applications

#### Pattern 3: Hybrid Approach (Recommended)

```
wwwroot/
├── css/
│   ├── site.css              # Global
│   └── pages/                # Page-specific
│       ├── pokemon.css
│       └── trainer.css
├── js/
│   ├── site.js               # Global
│   └── modules/              # Feature modules
│       ├── pokemon.js
│       └── trainer.js
├── images/
│   ├── pokemon/
│   ├── trainers/
│   └── common/
└── lib/                      # Third-party libraries
    ├── bootstrap/
    ├── jquery/
    └── toastr/
```

### Minification and Bundling

**For production, minify CSS and JavaScript:**

**Development files:**
- `site.css` - Full, readable version
- `pokemon.js` - Full, readable version

**Production files:**
- `site.min.css` - Minified version
- `pokemon.min.js` - Minified version

**Conditional loading in _Layout.cshtml:**

```cshtml
<environment include="Development">
    <link rel="stylesheet" href="~/css/site.css" asp-append-version="true" />
    <script src="~/js/site.js" asp-append-version="true"></script>
</environment>

<environment exclude="Development">
    <link rel="stylesheet" href="~/css/site.min.css" asp-append-version="true" />
    <script src="~/js/site.min.js" asp-append-version="true"></script>
</environment>
```

**Note:** The `<environment>` tag helper requires `Microsoft.AspNetCore.Mvc.TagHelpers`.

### CDN with Local Fallback

**Use CDN for performance, with local fallback:**

```cshtml
<!-- Bootstrap from CDN -->
<link rel="stylesheet"
      href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.2/dist/css/bootstrap.min.css"
      asp-fallback-href="~/lib/bootstrap/dist/css/bootstrap.min.css"
      asp-fallback-test-class="sr-only"
      asp-fallback-test-property="position"
      asp-fallback-test-value="absolute" />

<!-- jQuery from CDN -->
<script src="https://code.jquery.com/jquery-3.7.1.min.js"
        asp-fallback-src="~/lib/jquery/dist/jquery.min.js"
        asp-fallback-test="window.jQuery">
</script>
```

**How it works:**
1. Try loading from CDN
2. If CDN fails, load from local wwwroot
3. Provides reliability and performance

### Image Optimization

**Best practices for images:**

```css
/* Responsive images */
img {
    max-width: 100%;
    height: auto;
}

/* Pokemon sprites - small files */
.pokemon-sprite {
    width: 96px;
    height: 96px;
    image-rendering: pixelated; /* For pixel art */
}

/* Background images - optimize quality */
.hero-background {
    background-image: url('/images/backgrounds/hero-sm.jpg');
}

@media (min-width: 768px) {
    .hero-background {
        background-image: url('/images/backgrounds/hero-md.jpg');
    }
}

@media (min-width: 1200px) {
    .hero-background {
        background-image: url('/images/backgrounds/hero-lg.jpg');
    }
}
```

**Image format guidelines:**
- **JPEG** - Photos, complex images (use 70-85% quality)
- **PNG** - Images with transparency, screenshots
- **SVG** - Icons, logos, simple graphics (best quality, smallest size)
- **WebP** - Modern format, smaller than JPEG/PNG (use with fallbacks)

### Security Considerations

**Do's:**

✅ **Only put public files in wwwroot**
```
wwwroot/              ← Public (safe)
├── css/
├── js/
└── images/

src/                  ← Private (protected)
├── Controllers/
├── Models/
└── Views/
```

✅ **Sanitize user-uploaded file names**
```csharp
// Dangerous ❌
var fileName = userInput;

// Safe ✅
var fileName = Path.GetFileName(userInput);
var safeName = Regex.Replace(fileName, @"[^a-zA-Z0-9_\-\.]", "");
```

✅ **Set proper content types**
```csharp
return File(fileBytes, "application/pdf", "pokemon-guide.pdf");
```

**Don'ts:**

❌ **Don't store sensitive files in wwwroot**
- Configuration files
- Database files
- API keys
- Source code

❌ **Don't allow direct file uploads to wwwroot**
```csharp
// Bad ❌ - Security risk
var uploadPath = Path.Combine(_environment.WebRootPath, "uploads", fileName);

// Good ✅ - Validate first, store outside wwwroot
var uploadPath = Path.Combine(_environment.ContentRootPath, "UserUploads", safeFileName);
```

❌ **Don't enable directory browsing in production**

### Performance Best Practices

**1. Use Cache-Control headers**
```csharp
app.UseStaticFiles(new StaticFileOptions
{
    OnPrepareResponse = ctx =>
    {
        // Cache for 1 year
        const int durationInSeconds = 60 * 60 * 24 * 365;
        ctx.Context.Response.Headers[HeaderNames.CacheControl] =
            "public,max-age=" + durationInSeconds;
    }
});
```

**2. Compress static files**

Enable response compression in Program.cs:

```csharp
builder.Services.AddResponseCompression(options =>
{
    options.EnableForHttps = true;
});

var app = builder.Build();

app.UseResponseCompression();
app.UseStaticFiles();
```

**3. Use asp-append-version**

Always use version tagging to prevent stale cache:

```cshtml
<link rel="stylesheet" href="~/css/site.css" asp-append-version="true" />
```

**4. Lazy load images**

```html
<img src="~/images/pokemon/pikachu.png"
     loading="lazy"
     alt="Pikachu" />
```

**5. Serve appropriately sized images**

Don't serve 4000x3000 images when you only need 400x300:

```cshtml
<!-- Bad ❌ - Large file -->
<img src="~/images/pokemon-large.jpg" width="200" />

<!-- Good ✅ - Appropriately sized -->
<img src="~/images/pokemon-thumbnail.jpg" width="200" />
```

### Common Patterns Summary

| Pattern | Use Case | Example |
|---------|----------|---------|
| **Global styles** | Site-wide CSS | `site.css` in _Layout.cshtml |
| **Page-specific CSS** | Styles for one page/feature | `pokemon.css` in @section Styles |
| **Versioned assets** | Prevent cache issues | `asp-append-version="true"` |
| **CDN + Fallback** | Performance + reliability | CDN URL with asp-fallback |
| **Environment-specific** | Dev vs Production | `<environment>` tag helpers |
| **Organized folders** | Maintainable structure | Separate css/, js/, images/ |
| **Minified production** | Smaller file sizes | site.min.css for production |

## Troubleshooting Common Issues

### Issue 1: Static Files Not Loading (404 Error)

**Symptoms:**
- Browser shows 404 error for `/css/site.css`
- Styles or scripts don't apply

**Causes & Solutions:**

**1. File not in wwwroot:**
```
❌ src/css/site.css          (Wrong location)
✅ wwwroot/css/site.css       (Correct)
```

**2. UseStaticFiles() not called:**
```csharp
// Add to Program.cs
app.UseStaticFiles();
```

**3. Wrong path in HTML:**
```cshtml
❌ <link href="/wwwroot/css/site.css" />
✅ <link href="~/css/site.css" />
```

### Issue 2: Changes Not Appearing (Caching)

**Symptoms:**
- Updated CSS/JS but changes don't show
- Need to force refresh (Ctrl+F5)

**Solutions:**

**1. Add version tag:**
```cshtml
<link rel="stylesheet" href="~/css/site.css" asp-append-version="true" />
```

**2. Clear browser cache:**
- Chrome: Ctrl+Shift+Delete
- Or use incognito mode for testing

**3. Disable caching in development:**
```csharp
if (app.Environment.IsDevelopment())
{
    app.UseStaticFiles(new StaticFileOptions
    {
        OnPrepareResponse = ctx =>
        {
            ctx.Context.Response.Headers.Append("Cache-Control", "no-cache, no-store");
        }
    });
}
```

### Issue 3: Images Not Displaying

**Check:**

1. **File exists:** `wwwroot/images/logo.png`
2. **Correct path:** `<img src="~/images/logo.png" />`
3. **File extension matches:** `logo.png` not `logo.PNG` on Linux
4. **File permissions:** Ensure IIS/server can read the file
